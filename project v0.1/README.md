# 🛡️ Комплекс Охраны: PTZ-Турель & DoorGuardian IoT (v0.1)

Распределённая отказоустойчивая система видеонаблюдения, контроля периметра и удалённого телеметрического управления. Комплекс работает через выделенный облачный VPS-ретранслятор без необходимости проброса портов (NAT) и без статических IP-адресов на контролируемом объекте.

---

## 🌐 Рабочий адрес комплекса

* **Публичный защищённый веб-интерфейс:** [https://lk-best.vibecoder.help/](https://lk-best.vibecoder.help/)
* **Резервный порт прямого доступа:** `http://188.120.230.91:18080/`
* **Архитектура портов на VPS:**
  * **Порт 443 (HTTPS / TLS 1.3):** внешний мультиплексор Nginx перенаправляет трафик по SNI домена `lk-best.vibecoder.help` на защищённый локальный порт `127.0.0.1:8443`.
  * **Порт 80 (HTTP):** авто-редирект на HTTPS + обработка ACME-челленджей Let's Encrypt через `/var/www/certbot`.
  * **Порт 18080 (HTTP):** прямой резервный порт Nginx без TLS для микроконтроллеров.
  * **Порт 18081 (HTTP Local):** ядро ретранслятора `server.py` на `127.0.0.1`.

> ⚠️ **СТРОЖАЙШЕЕ ПРАВИЛО БЕЗОПАСНОСТИ VPS (ZERO-TOUCH POLICY):**  
> На сервере в зашифрованном LUKS-хранилище параллельно работает закрытый сервис (`/opt/syngram`).  
> **Категорически запрещено:**
> 1. Затрагивать каталог `/opt/syngram` или файлы `/etc/nginx/sites-enabled/syngram-site`.
> 2. Выполнять перезагрузку всей операционной системы (`reboot` / `shutdown`).
> 3. Выполнять массовые обновления пакетов (`apt upgrade`, `apt dist-upgrade`).
> 4. Все работы на сервере ограничены каталогом `/root/turret_bridge/` и файлом `/etc/nginx/conf.d/turret.conf`.

⚙️ Аппаратная спецификация и распиновка
1. Контроллер исполнительных механизмов: Arduino Uno (turret_head/)
Управляет сервоприводами поворотной головы, ультразвуковым сонаром и датчиком освещённости.

Пин D10 (Pan Servo): сервопривод поворота по горизонтали.
Рабочий физический диапазон: от 150° до 181°.
Центральная точка: 165°.
Внимание: в коде EEPROM защита валидации ограничена строго значением 300 (не изменять).
Пин D11 (Tilt Servo): сервопривод наклона по вертикали.
Рабочий физический диапазон: от 85° до 165°.
Центральная точка: 125°.
Пин D12 (Trig) и Пин D2 (Echo): ультразвуковой дальномер HC-SR04.
Нюанс: пин Echo перенесён с D13 на D2, так как встроенный на плату Uno светодиод L на D13 вносил помехи в длительность импульса.
Пин A0: аналоговый датчик освещённости (подключается строго к контакту AO модуля фоторезистора).
Пины D0 (RX) и D1 (TX): связь с видеошлюзом по аппаратному UART на скорости 115200 бод.
⚠️ КРИТИЧЕСКИ ВАЖНО ПРИ ПРОШИВКЕ: Перед загрузкой скетча в Arduino Uno обязательно отсоединяйте провода от пинов D0 и D1, иначе программатор выдаст ошибку синхронизации stk500_getsync().
2. Видеошлюз: ESP32-S3 Cam (esp32s3_camera/)
Плата: ESP32S3 Dev Module с внешней памятью OPI PSRAM (N8R8).

Сенсор: OV2640. Разрешение: VGA (640x480), jpeg_quality = 12.
Аппаратные фильтры DSP сенсора: включена встроенная резкость матрицы sharpness = 2 и контраст contrast = 2, размытие шумов отключено denoise = 0 для максимальной частоты кадров. Камера перевёрнута: vflip = 1, hmirror = 1.
Связь с Arduino Uno:
ESP32 GPIO 39 (TX) 
⟶
⟶ Arduino Uno D0 (RX)
ESP32 GPIO 40 (RX) 
⟵
⟵ Arduino Uno D1 (TX)
Сетевой движок (Параллельный стриминг):
Стек lwIP в ESP32-Arduino имеет фиксированное окно передачи TCP ~5.7 КБ. При пинге мобильного 4G-интернета (100–150 мс) скорость одного сокета ограничена физическим пределом ~45 КБ/с (1–2 FPS).
Проблема решена конвейером из 5 параллельных TCP-сокетов Keep-Alive на ядре Core 0. Кадры маркируются заголовком X-Seq. Сервер отбрасывает кадры, пришедшие не по порядку. Это обеспечивает стабильные 12–18 FPS при малом весе кадра (~20 КБ).
3. Автономный охранный модуль: DoorGuardian (esp32_doorguardian/)
Плата: ESP32 Dev Module (WROOM-32). Полностью независим от турели.

GPIO 4: геркон двери (INPUT_PULLUP, замыкание на GND при закрытии).
GPIO 21: тактовая кнопка (INPUT_PULLUP, ручная постановка / снятие).
GPIO 16: статусный светодиод.
GPIO 5: пассивный пьезозуммер. При тревоге воспроизводит тему Тореадора из FNAF.
Охранная логика:
При постановке на охрану активируется режим STATE_ARMING: 15-секундная задержка на выход с учащающимися звуковыми сигналами.
Сетевой стек работает в независимой задаче FreeRTOS networkTask. Все функции охраны, считывание геркона и сирена работают автономно даже при полном обрыве Wi-Fi.
📡 Спецификация REST API облачного моста (server.py)
Сервер представляет собой асинхронный HTTP-шлюз на Python 3 (127.0.0.1:18081), принимающий данные от микроконтроллеров и отдающий их клиентским приложениям.

1. Видеотрансляция и управление PTZ:
Метод	Эндпоинт	Описание
GET	/stream	Непрерывный поток multipart/x-mixed-replace; boundary=frame. Поддерживает прямое отображение в <img src="...">.
GET	/snapshot	Возвращает единичный JPEG-кадр (image/jpeg). Идеально для компьютерного зрения и детекции лиц/объектов.
GET	/cmd?c={CMD}	Отправка команды управления турелью. Допустимо: U, D, L, R, C.
GET	/telemetry	Возвращает строку телеметрии турели в формате: DIST=..;LIGHT=..;PAN=..;TILT=..
Аппаратная инверсия по вертикали:
Из-за расположения качалки сервопривода D11 уменьшение угла поднимает объектив вверх, а увеличение опускает вниз.
Сервер server.py автоматически инвертирует входящие команды: отправка U (Up) транслируется мотору как подъём, а D (Down) — как опускание. Разработчику фронтенда и ИИ нужно слать интуитивно понятные команды:

U — вверх, D — вниз, L — влево, R — вправо, C — центрировать.
2. Модуль охраны двери (DoorGuardian):
Метод	Эндпоинт	Описание
GET	/door_status	Возвращает строку: DOOR=CLOSED;STATE=ARMED;AGE=180.<br>DOOR: OPEN / CLOSED<br>STATE: DISARMED, ARMING_14s, ARMED, ALARM<br>AGE: возраст отчёта в мс (-1 при оффлайне).
GET	/api/door_cmd?c={CMD}	Удалённое управление охраной двери. Параметр c: ARM (поставить на охрану) или DISARM (снять / заглушить сирену).
GET	/api/door_report	Служебный эндпоинт для ESP32 DoorGuardian. Принимает телеметрию и отдаёт отложенные команды управления.
🛠️ Задачи для следующего разработчика
Создание современного фронтенда (Web UI Dashboard):

Встроенный в server.py HTML-пульт является базовым.
Требуется разработать современный SPA-дашборд (React / Vue / Tailwind CSS или легковесный Vanilla JS).
Требования к UI:
Видеопоток во весь экран с адаптацией под смартфоны и планшеты.
Управление PTZ через экранный джойстик или зажатие экранных кнопок (pointerdown / pointerup с защитой от случайного вызова контекстного меню).
Управление с клавиатуры: стрелки или клавиши W, A, S, D, пробел — центр.
Виджеты телеметрии: шкала дистанции HC-SR04, уровень освещённости, текущие углы серв.
Панель охраны периметра: статус двери (геркон), кнопка экстренного сброса тревоги DISARM, кнопка постановки на охрану ARM с отображением 15-секундного таймера.
